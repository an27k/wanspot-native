# 同伴可否判定の正解セット

`pet-policy-gold.json` — 東京都心部40件を、公式サイト・掲載系サイト（ぐるなび／ホットペッパー／
一休等）・Google口コミから独立に調べた結果。2026-08-18 作成。各件に根拠URLか原文引用が入っている。

## 何のためにあるか

検証パイプラインには合否判定が無く、実行しても精度が測られない。だから何度回しても
同じ誤りを繰り返し、失敗が失敗として記録されない。作成時点の実測は次のとおり。

| | |
|---|---|
| 全体（判定可能32件） | 65.6% |
| 飲食店・公園・ホテルのみ | **56.0%** |
| 現地で断られうる件 | 17.5% |

全体65.6%は水増し。一致21件のうち7件は動物病院・ドッグランで、カテゴリだけで自明に
allowed になる施設。精度を報告するときは必ずカテゴリ別に分けること。

## 使い方

パイプラインを変更したら、**本番へ流す前にこの40件だけで走らせて精度を測る**。
40件 × 約$0.09 ≈ **$3.6**。何度でも回せる。基準を満たしてから初めて全件に金を使う。

## 精度の数え方

- `truth = undeterminable`（8件）は分母から外す。情報が世に存在しない群で、
  ここを埋めさせると精度が実態より良く出る
- `confidence = low`（9件）も分母から外す
- **カテゴリ別に出す。** 動物病院・ドッグランは自明なので、飲食店・公園の数字を主指標にする
- **誤りの向きを分ける。** DBが実際より緩い（現地で断られる）誤りは、厳しすぎる誤りより
  コストが高い。同じ1件として数えない

## 出荷基準（案）

飲食店・公園カテゴリで、
- 現地で断られうる誤り（db_too_permissive）が **0件**
- 全体一致率 **98%以上**

これを満たすまで本番バッチを流さない。

## 既知の誤りの型（作成時点）

1. 検索の失敗を「情報が無い」として確定させる（花園公園: notes に
   「web検索は今回ツール上限により実施できず」と書きながら leashed_only）
2. 「記載なし」を「可」の方向に読む（断られる側の誤りのほぼ全て）
3. 公式サイトで探索を打ち切る（誤り8件は掲載系サイトに明記があった）
4. 条件（ケージ必須・抱っこ必須・サイズ制限）を落とす
