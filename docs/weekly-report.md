# 週次レポート（今週のモカ）— 設計メモ ＆ 広告マネタイズ検討

> 対象: `wanspot-native`。ユーザーに毎週「今週の愛犬の振り返り」を届ける機能の計画メモ。
> 本書の主目的は **広告を入れる場合の配置・タイプ・想定利益** を検討要素として残すこと。

## 0. 機能の前提（ざっくり）

週1回、ユーザーに「今週のモカ」を提示する振り返り体験。

- 含める要素（候補）: 今週の散歩回数 / 訪問スポット / 撮った写真・動画 / 快適度・気温の推移 / 連続記録（ストリーク）/ VLOG 進捗（5スポット中◯）/ おすすめの次の一歩。
- 表示面（候補）: 検索タブ上部の差し込みカード、アルバム/VLOG タブのヘッダー、プッシュ通知からのレポート全画面、`/weekly` モーダル。
- 頻度: 週1（例: 月曜朝に確定 → 通知）。**「特別な振り返り」体験**なので広告は最小限・高品質に絞るのが原則。

---

## 1. 広告マネタイズ検討（本題）

### 1.1 現状の広告基盤（流用前提）

| 部品 | 場所 | 内容 |
|---|---|---|
| マスタースイッチ | `constants/ads.ts`（`ADS_ENABLED`） | 既定 OFF。`EXPO_PUBLIC_ADS_ENABLED=true` で全広告を有効化 |
| 端末ポリシー | `lib/ads-policy.ts`（`adsEnabledForDevice`） | フラグ＋端末条件 |
| リスト注入 | `lib/ads/list-injection.ts`（`LIST_AD_ROW_EVERY=5`） | リスト5件ごとにネイティブ広告行 |
| ネイティブ広告カード | `components/ads/NativeAdStandardCard.tsx` / `components/AdNativeCard.tsx` | AdMob ネイティブ（advanced） |
| AIプラン枠 | `components/ai-plan/AiPlanResultAd.tsx` / `AiPlanGeneratingAd.tsx` | 結果・生成中の広告 |

→ **AdMob ネイティブ広告**が中核。週次レポートも同じ `NativeAdStandardCard` を流用でき、追加 SDK は不要。

### 1.2 配置候補（どこに）

優先度は「体験を壊さず、視認は確実に取れる」順。

| # | 配置 | フォーマット | 体験への影響 | 推奨度 |
|---|---|---|---|---|
| A | レポート末尾（振り返りを読み終えた後の1枠） | ネイティブ（記事カード調） | 低（区切り後で自然） | ★★★（第一候補） |
| B | セクション間に1枠（散歩サマリー ↔ 写真ハイライトの境） | ネイティブ（インフィード） | 中（流れを割る） | ★★ |
| C | レポートを「開く」導線にリワード型（広告を見て限定スタンプ/壁紙を解放） | リワード | 低〜中（任意視聴） | ★★（高単価・任意性が鍵） |
| D | レポート閉じ際のインタースティシャル | 全画面 | 高（離脱要因） | ★（非推奨。週次の特別感を損なう） |

**推奨方針**: まず A（末尾ネイティブ1枠）のみ。エンゲージが高ければ C（任意リワード）を追加。B/D は慎重に。1レポートあたり広告は **1〜2枠まで**（週次＝低頻度ゆえ詰め込まない）。

### 1.3 広告タイプ別 想定 eCPM（日本・2026 目安）

AdMob 実績レンジの一般的な目安（媒体・季節で大きく変動。確定値は実配信で要計測）。

| タイプ | eCPM（¥/1000 imp）目安 | 備考 |
|---|---|---|
| バナー | ¥100〜300 | 単価低。週次の特別画面には不向き |
| ネイティブ（advanced） | ¥400〜900 | 記事調に馴染む。**本命** |
| インタースティシャル | ¥600〜1,500 | 単価高だが離脱・ポリシーリスク |
| リワード | ¥1,000〜3,000 | 最高単価。**任意視聴**前提なら体験毀損が小さい |

### 1.4 利益見積りモデル（いくら）

月間収益の基本式:

```
月間収益 = MAU × レポート開封率 × 1レポートの広告表示数 × 月の週数(4.3) × (eCPM / 1000) × 充填率
```

**共通前提**: レポート開封率 60%、充填率（fill rate）90%、月 4.3 週。

#### シナリオ A: 末尾ネイティブ1枠のみ（推奨 MVP）

- 広告表示数/レポート = 1、ネイティブ eCPM = ¥650（レンジ中央）

| MAU | 月間広告 imp | 月間収益（概算） | 年換算 |
|---|---|---|---|
| 1,000 | ≈ 2,300 | **約 ¥1,300/月** | 約 ¥1.6万 |
| 10,000 | ≈ 23,000 | **約 ¥1.3万/月** | 約 ¥16万 |
| 50,000 | ≈ 115,000 | **約 ¥6.7万/月** | 約 ¥80万 |

#### シナリオ B: 末尾ネイティブ + 任意リワード（解放型）

- ネイティブ1枠（eCPM ¥650, 表示60%）＋ リワード（eCPM ¥1,800, 視聴率 25%）

| MAU | 月間収益（概算） | 年換算 |
|---|---|---|
| 1,000 | **約 ¥2,300/月** | 約 ¥2.8万 |
| 10,000 | **約 ¥2.3万/月** | 約 ¥28万 |
| 50,000 | **約 ¥11.6万/月** | 約 ¥140万 |

※ いずれも **粗利（AdMob 取り分控除後の管理画面表示額ベース）**。実効値は配信地域・ジャンル一致・季節（Q4高、1月低）で ±50% 程度ぶれる前提。

### 1.5 感応度（収益を左右する順）

1. **MAU と開封率** — 週次は表示機会が月次比で少ない。プッシュ通知の開封導線が収益の主役。
2. **広告タイプ** — リワード＞ネイティブ＞バナー。任意リワードの導入有無で +70〜100%。
3. **eCPM の季節変動** — Q4（11〜12月）は +30〜50%、年始は低下。
4. **充填率/地域** — 日本中心なら fill は高め。

### 1.6 ガードレール（体験・ポリシー）

- 週次の「特別な振り返り」を壊さない: **1レポート最大1〜2枠**、全画面強制（D）は原則不可。
- AdMob ポリシー: 偶発クリック誘発配置（CTA直下に広告 等）を避ける。コンテンツと広告のラベル明示。
- リワードは **完全に任意**（見なくてもレポートは全閲覧可。報酬は装飾系のみ）。
- 既存 `ADS_ENABLED` / `adsEnabledForDevice()` の配下に置き、OFF 時はプレースホルダも出さない（現行リスト注入と同じ流儀）。
- 計測: 表示・クリックを `lib/user-events.ts` に記録し、配置別 eCPM を後から比較して A/B 判断。

### 1.7 結論（検討要素としての推奨）

- **MVP**: 配置 A（末尾ネイティブ1枠）。追加 SDK 不要・既存カード流用。小規模 MAU では収益は小さい（数千円〜数万円/月）が、**実装コストほぼゼロ**で計測基盤を作れる。
- **伸ばす一手**: 配置 C（任意リワードで限定スタンプ/壁紙解放）。体験を保ったまま単価最大化。MAU 1万で月 +1万円規模。
- **やらない**: 配置 D（閉じ際インタースティシャル）。週次体験の価値毀損リスクが利益を上回る。
- **収益の前提**: 数字は MAU・開封率・eCPM 次第。本機能単体は「主収益」ではなく **リテンション機能のついで収益**と位置づけ、まずは A で計測 → データを見て C を判断する。
