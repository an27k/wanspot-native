## 2. 画面別設計

### 2.1 検索タブ（マップ＋検索統合）

現行マップ画面（v96実装: 全スポットピン・ノーマルピン・カルーセル・じょうご条件フィルタ）に検索を載せる。

**レイアウト（上→下）**:
1. **検索バー**（マップ上部オーバーレイ・ワンナビ型）: 「目的地を検索する」。GlassSearchShell を流用
2. その下に既存のフィルタバー（じょうご＋ジャンルチップ）
3. マップ本体＋下部カルーセル（既存のまま）

**テキスト検索の挙動（設計判断・推奨）**:
- 検索実行 → 結果スポットを**そのままマップのピン＋カルーセルに流す**（別画面のリストを出さない。マップ文脈で一貫）
- サーバーの `search_center`（駅・エリア解決）が返れば**マップをその中心へアニメ移動**。遠方検索がそのまま成立する
- 検索結果表示中はフィルタバー位置に「検索結果 ◯件 ×クリア」のバーを出し、×で通常の現在地表示へ戻る
- サジェストタグ（大型犬可・雨の日OK等）は検索バーのフォーカス時にバー直下へチップ表示（未フォーカス時は出さない＝地図の視界を汚さない）
- ソート（近い順/評価順）はカルーセルの並びに適用。じょうご内に「評価順」トグルを足すか検索結果バーに置く（実装時に軽い方）

**移動・廃止**:
- WalkAlertCard・LikesShortcutCard・まとめ記事フィード・SearchHomeHeader → 検索タブから撤去（行き先は下記）
- AIプラン/AIレコメンドのピル: 既にフラグoff。ホスト（search.tsx）解体後も AiPlanTab 等のコードは温存し、フラグ復旧時の再配置先は「検索バー付近」と本書に記録しておく
- `SEARCH_STORAGE_KEY`（検索状態復元）: マップ統合版に移行（query・searchCenter のみ。スクロール位置は不要になる）

### 2.2 まとめ記事タブ（ワンスポまとめ）

- search.tsx の記事フィード部（`handleArticles` / `personalizeArticlesFeed` / `DiscoverFeedCard` / 広告挿入 `shouldInjectListAd`）を `components/articles/ArticlesTabScreen.tsx` として抽出
- ヘッダー: 「ワンスポまとめ」タイトルのみのシンプル構成（検索バーは置かない。記事内検索が必要になったら後続）
- 記事詳細は既存 `app/articles/[id].tsx` をそのまま利用
- パーソナライズ（walk-area タグ加点）・pull-to-refresh・キャッシュ挙動は現行を維持

### 2.3 カレンダータブ（ワンスポカレンダー移植）

**データ契約（Web実装確認済み）**:
- 月別: `GET /api/calendar/events?year=&month=`（＋任意 `prefectureId` / `regionId` / `stationId` / `q` / `tagIds`）
  - 返却: `{ events: CalendarEventWithRelations[] }`。CDN 5分キャッシュ
  - イベントは `ai_summary`・`price_level`（0=無料、1〜4=¥〜¥¥¥¥）・`related_urls`（①=official_url 先頭）・`ticket_url`・`last_entry_text`・`occurrences[]`・`tags[]`・`venue_name`・`lat/lng` 込み
- **個別イベントAPIは存在しない**（`/events/[slug]` はWebページ）。アプリの詳細画面は**月別レスポンスのイベントをそのまま渡して描画**する（追加API不要で開始できる）。
  外部からslug直リンクを受ける必要が出たら `/api/calendar/events/[slug]` をサーバーに追加（S規模・後続）
- **日時は常にJST表示**。`Intl.DateTimeFormat('ja-JP', { timeZone: 'Asia/Tokyo' })` に統一し、端末タイムゾーンに依存させない（既存 walk-advice の实装と同じ流儀）

**画面構成**:
1. **月ビュー**: 月送りヘッダー＋グリッド（イベントのある日にタグ色ドット、`CalendarDayEvent.tagColor` 相当）。地域フィルタ（都道府県）は初版ではヘッダーの1ピッカーのみ（regionId/stationId 絞りは後続）
2. **日別リスト**: グリッド下に選択日のイベントカード（サムネ・タイトル・時間・会場・料金ランク）
3. **イベント詳細**（`app/calendar/[slug].tsx`・タブ外プッシュ画面）:
   - サムネイル、タイトル、開催日時（occurrences・JST・最終入場）、会場（venue_name/address、lat/lng があれば地図タブへ「地図で見る」導線）
   - **AIまとめカード: 既存「ワンスポAIレビュー」カードのデザインを共通化して流用**（`components/common/AiSummaryCard.tsx` に抽出 → スポット詳細とカレンダー詳細の2箇所から使用）。カレンダーでは `ai_summary` テキストをそのまま表示（生成呼び出しなし）
   - 料金ランク（0=無料バッジ、1〜4=¥表記。スポットの price_label と同系の見た目）
   - 関連URL（①②③…の番号付きリンク行。①=公式。外部ブラウザで開く）、チケットURL
4. キャッシュ: 月単位で client-cache（TTL 30分目安。サーバー側5分CDNがあるため軽く）

**経緯との整合**: アプリのイベント機能（作成・決済・参加）は廃止済みだが、本件は**読み取り専用の情報タブ**であり、廃止したソーシャル/決済機能の復活ではない（P7「イベント=情報」の最小構成と同方針）。

### 2.4 設定タブ（統合）

現行の設定タブ（愛犬/サポート/アカウントの3グループ）に2セクションを追加:

1. **お散歩予報**（最上部・愛犬グループの上）: WalkAlertCard＋WalkAlertModal を検索タブから移設。
   - 毎朝7:00のプッシュ通知の遷移先を `/(tabs)/search` → `/(tabs)/mypage` に変更（**通知が設定タブへの日常導線になる**）
   - 飼い主視点の注意: 設定タブは低頻度タブのため、アラートの日常接点は朝の通知が主になる。通知許可の同期呼び出しも設定タブ側に移す
2. **いいね一覧**: 「いいねしたスポット」行を愛犬グループ付近に追加 → 既存 `app/likes.tsx` へ遷移（画面はそのまま流用）。LikesShortcutCard は廃止（行導線に置換）

## 4. 横断的な影響と対応

- **通知ディープリンク**: `walk_advice_morning` の url を設定タブへ。`memory_anniversary` のフォールバック先 `/(tabs)/search` も `/(tabs)/index` に変更
- **タブ analytics**: `tab_viewed` の tab_name を新4タブ名に更新（search/articles/calendar/mypage）
- **initialRouteName**: `index`（検索=マップ）に変更
- **beforeNavSearch / SEARCH_RESTORE_FLAG**: マップ統合版で簡素化（詳細画面→戻るの状態保持はマップ側 state が生きているため、AsyncStorage 復元の役割は縮小）
- **spot詳細からの導線**: openSpotDetail は不変。カレンダー詳細→「地図で見る」は place_id があれば openSpotDetail、なければ座標センタリングのみ
- **Places コスト**: 検索がマップ統合されても検索APIの呼び出し頻度自体は不変。カレンダーはDB読みのみでコスト影響なし
